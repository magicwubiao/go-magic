# Chat 打断机制 & 需求管理

在 `magic chat` 交互过程中，AI 正在生成回答时，可以随时**打断**它并添加新的需求，AI 会记住这些需求并在后续对话中优先处理。

## 使用场景

| 场景 | 说明 |
|------|------|
| 💡 想到新需求 | AI 正在写代码时，突然想到一个新功能需要加入 |
| 🐛 发现新 Bug | 测试中发现了 Bug，需要 AI 优先修复 |
| 🔄 变更需求 | 当前方案不符合实际，需要调整方向 |
| 📝 记录任务 | 不想打断当前对话，先把需求记下来 |

## 快速使用

### 方法 1：在对话中直接说（推荐）

当 AI 正在回答时，直接输入你的新需求：

```
[AI 正在生成回答...]

> 等等，我想到一个新需求：需要添加用户认证功能
```

AI 会：
1. ✅ 记住当前进度
2. ✅ 记录新需求到待办列表
3. ✅ 在接下来的回答中优先处理

### 方法 2：使用 `/req` 命令快速添加需求

```
> /req 添加用户登录页面
> /req --priority high 修复数据库连接超时问题
> /req 需要生成 API 文档
```

### 方法 3：在对话中间打断

```
> 先停一下，我有个新想法：我们需要支持导出为 PDF 格式
  [然后继续原来的对话]
```

## 命令参考

### 需求管理命令

| 命令 | 说明 | 示例 |
|------|------|------|
| `/req <内容>` | 添加新需求 | `/req 添加用户登录` |
| `/reqs` | 查看所有待处理需求 | `/reqs` |
| `/req-done <id>` | 标记需求已完成 | `/req-done todo_123` |
| `/req-del <id>` | 删除需求 | `/req-del todo_123` |
| `/req-priority <id> high` | 设置需求优先级 | `/req-priority todo_123 high` |

### 打断相关命令

| 命令 | 说明 |
|------|------|
| `/stop` | 停止当前生成 |
| `/context` | 查看当前对话上下文和积累的需求 |
| `/continue` | 继续之前的对话（打断后） |

## 工作流程

### 典型工作流

```
1. 开始对话
   > 帮我写一个用户注册功能

2. AI 开始生成代码...
   [正在生成代码...]

3. 突然想到新需求 → 打断
   > 等等，再加一个邮箱验证功能

4. AI 处理请求：
   ✓ 记录需求: "添加邮箱验证功能"
   ✓ 整合到当前代码中

5. 继续对话
   > 好的继续吧

6. AI 继续生成，包含新需求
```

### 需求优先级管理

```
优先级: 🔴 High > 🟡 Medium > 🟢 Low

/req --priority high 生产环境紧急Bug修复
/req --priority medium 添加日志功能  
/req --priority low 优化代码注释
```

## 需求存储

所有需求自动保存到 `~/.magic/todos/todos.json`，即使退出会话也能保留。

## 最佳实践

### ✅ 推荐做法
- 打断时快速说出需求要点
- 使用 `/req` 命令快速记录
- 完成后及时标记已完成
- 给需求设置合理的优先级

### ❌ 不推荐做法
- 打断时给出过长描述（应简洁）
- 一次打断添加太多需求（分批添加）
- 不标记已完成的需求（会积累混乱）
