# Web Fetch 技能

本技能配套两个 `ap_web-fetch_cli_curl_*` 工具，通过本机 `curl` 发起 HTTP 请求：

| 工具 | 语义 | 审批 |
| --- | --- | --- |
| `http_get` | GET 请求，`-fsSL`，跟随重定向，4xx/5xx 直接报错 | 免确认 |
| `http_post_json` | POST 请求，`Content-Type: application/json` | **需要用户确认** |

## 使用要点

1. **URL 必须是绝对地址**（带 `http://` 或 `https://`）。用户只给域名时主动补全 scheme。
2. 工具返回的是**原始响应体**。抓网页时输出可能很长：先向用户说明要找什么，再决定是否值得整页拉取；HTML 页面可以先在心里预期是标签文本，提炼正文再回答。
3. 调 JSON API 时，响应体直接就是 JSON，可以原样引用关键字段回答。
4. `http_post_json` 会修改远端状态（创建资源、触发 webhook 等），**调用前必须向用户复述将要发送的 URL 和 body**，确认无误再执行——审批弹窗是最后一道防线，不是替代确认的借口。
5. 超时参数按需调整：本地服务给 10 秒足够，公网大接口可放宽到 30–60 秒。
6. 不要用这两个工具做需要 Cookie/登录态的请求；那种需求引导用户配置专用连接器或 MCP。
7. 安全底线：不要请求用户未提及的内网地址、不要把凭据拼进 URL 查询串。
